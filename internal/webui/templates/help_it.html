{{call .T "guide_toc_synology"}}

Phorga gira direttamente sul NAS, in Container Manager. Servono DSM 7.2 o successivo e un account amministratore. Tutti i passaggi si fanno in DSM dal browser.

  1. Installa Container Manager. Centro pacchetti → cerca “Container Manager” → Installa. Se usi Synology Photos, il servizio home utente è già attivo; altrimenti attivalo in Pannello di controllo → Utente e gruppo → Avanzate → Home utente.
  2. Crea un utente per Phorga. Pannello di controllo → Utente e gruppo → Crea. Chiamalo phorga e dagli una password lunga e casuale (non ti servirà più). Nei permessi delle cartelle condivise, dai Lettura/Scrittura a docker e homes. Nei permessi delle applicazioni nega tutto; Phorga non accede mai a DSM.
  3. Crea le cartelle. In File Station apri docker, crea la cartella phorga e al suo interno le cartelle config e state.
  4. Trova l'ID utente. Pannello di controllo → Utilità di pianificazione → Crea → Attività pianificata → Script definito dall'utente. Nome phorga id, utente root, togli la spunta da “Abilitato”; nelle impostazioni dell'attività inserisci il comando id phorga > /volume1/docker/phorga/id.txt. Salva, seleziona l'attività, fai clic su Esegui e apri docker/phorga/id.txt in File Station: uid=1030(phorga) gid=100(users) significa 1030:100. Poi elimina l'attività.
  5. Crea il progetto. Container Manager → Progetto → Crea. Nome del progetto phorga, percorso /docker/phorga, origine “Crea docker-compose.yml”, e incolla: 
    {{.Data.ComposeSynology}}
    Sostituisci 1030:100 con i numeri del passaggio 4 e choose-a-long-password con la tua password per l'interfaccia web. Avanti, salta le impostazioni del portale web, Fine. Container Manager scarica Phorga e lo avvia.
  6. Rendilo raggiungibile in HTTPS. Pannello di controllo → Portale di accesso → Avanzate → Proxy inverso → Crea: nome Phorga; origine protocollo HTTPS, nome host *, porta 8443; destinazione protocollo HTTP, nome host localhost, porta 8080. Salva. Se il firewall di DSM è attivo, consenti la porta 8443 (Pannello di controllo → Sicurezza → Firewall).
  7. Apri Phorga. Da un dispositivo della tua rete apri https://<indirizzo NAS>:8443/ui, ad es. https://192.168.1.20:8443/ui. Se il NAS usa un proprio certificato, il browser avvisa una volta; in casa è normale. Accedi con un nome utente qualsiasi e la tua password, poi continua con {{call .T "guide_toc_setup"}}.

{{call .T "guide_toc_other"}}

Phorga gira su un computer sempre acceso, come un Mac mini, un Intel NUC o un server di casa, e lavora sul NAS tramite una condivisione di rete.

  1. Installa Docker. macOS e Windows: Docker Desktop, con “Start Docker Desktop when you sign in” attivo nelle impostazioni. Linux: Docker Engine con il plugin Compose.
  2. Consenti l'accesso sul NAS. In DSM crea l'utente phorga con Lettura/Scrittura su homes (passaggio 2 della guida Synology) e verifica che SMB sia attivo (Pannello di controllo → Servizi file → SMB).
  3. Collega la condivisione. macOS: Finder → Vai → Connessione al server → smb://<indirizzo NAS>/homes, accedi come phorga; la condivisione appare come /Volumes/homes. Per ricollegarla dopo un riavvio, aggiungila in Impostazioni di Sistema → Generali → Elementi login. Linux: montala, ad esempio con questa riga in /etc/fstab (il file delle credenziali contiene username=phorga e password=…): 
    //192.168.1.20/homes  /mnt/nas-homes  cifs  credentials=/etc/phorga-nas,uid=1000,gid=1000,_netdev  0  0
  4. Crea il progetto. Crea una cartella phorga nella tua cartella home, con le cartelle config e state al suo interno, e salvaci questo come docker-compose.yml: 
    {{.Data.ComposeOther}}
    Imposta user: sull'output di id -u e id -g, la password sulla tua e, su Linux, la condivisione sul tuo punto di montaggio.
  5. Avvia Phorga. Nel terminale: cd ~/phorga && docker compose up -d. Apri http://127.0.0.1:8080/ui su questo computer, accedi con un nome utente qualsiasi e la tua password, e continua con {{call .T "guide_toc_setup"}}.
  6. Tienilo acceso. Il computer non deve andare in stop (macOS: Impostazioni di Sistema → Energia → Impedisci lo stop automatico). Il container vede solo una condivisione collegata al suo avvio: dopo averla ricollegata, esegui docker compose restart.

{{call .T "guide_toc_setup"}}

  1. Scegli gli utenti. Nella pagina di configurazione, “Utenti di Synology Photos” elenca chi ha una libreria Synology Photos. Spunta gli utenti i cui caricamenti dal telefono Phorga deve ordinare e fai clic su Aggiungi gli utenti selezionati.
  2. Controlla il profilo. Ogni utente riceve un profilo che ogni notte alle 03:00 sposta i nuovi file da Photos/MobileBackup a Photos/<anno>/<mese>. Parte come prova (dry run): Phorga scrive nel log solo cosa farebbe. Fai clic sul profilo per cambiare l'orario o la struttura delle cartelle.
  3. Salva. Il salvataggio scrive il file di configurazione e pianifica subito i job. Non serve riavviare.
  4. Controlla la prova. Dopo la prima esecuzione, la pagina di stato mostra quanti file verrebbero spostati, e il log del container elenca ogni file (Container Manager → Container → phorga → Registro, oppure docker compose logs phorga). Per provarlo subito, imposta la pianificazione su */5 * * * * (ogni 5 minuti) e poi rimettila com'era.
  5. Disattiva la prova. Se il log è corretto, apri il profilo, togli la spunta da Dry run e salva. Dalla prossima esecuzione Phorga sposta i file. Synology Photos li mostra nelle nuove cartelle dopo averli indicizzati. Dopo la prima esecuzione reale, verifica che l'app Synology Photos sul telefono non carichi di nuovo le foto spostate.
  6. Facoltativo: trova i duplicati. In “Job rilevamento duplicati” aggiungi un job che confronta cartelle e trova copie della stessa foto. Anche questo parte come prova e sposta i duplicati solo in una cartella a tua scelta; non cancella mai nulla.

{{call .T "guide_toc_remote"}}

Chi può aprire l'interfaccia web può cambiare quali file Phorga sposta. Proteggila così:

  • Imposta sempre una password con PHORGA_WEB_UI_PASSWORD, come nei file compose qui sopra. Scegline una lunga: dopo tentativi errati non viene bloccato nulla. Il browser la chiede una volta per sessione. Per cambiarla, modifica il file compose e ricrea il container (Container Manager → Progetto → phorga → Configurazioni YAML → Modifica, oppure docker compose up -d).
  • Synology: il proxy inverso (passaggio 6) aggiunge HTTPS e, poiché la porta del container resta su 127.0.0.1, il proxy è l'unico accesso. Per consentire solo la rete di casa, crea un profilo di controllo accessi (Pannello di controllo → Portale di accesso → Avanzate → Profilo di controllo accessi) che consente ad es. 192.168.1.0/24 e nega tutto il resto, e selezionalo nella regola del proxy inverso. Con un tuo dominio, usalo come nome host al posto di * e assegna il suo certificato in Pannello di controllo → Sicurezza → Certificato → Impostazioni.
  • Altro computer: cambia la porta in "8080:8080" ed esegui docker compose up -d. Poi apri http://<indirizzo computer>:8080/ui. Senza HTTPS la password attraversa la rete in chiaro, accettabile solo in una rete di casa di cui ti fidi; per HTTPS metti davanti un proxy inverso come Caddy.
  • Mai inoltrare la porta verso Internet nel router. Fuori casa collegati alla rete di casa con una VPN (ad esempio Synology VPN Server o Tailscale).

{{call .T "guide_toc_trouble"}}

“cartella home non trovata”
Il container non vede la cartella homes. Controlla il volume /volume1/homes:/homes; su un altro computer, che la condivisione sia collegata. Se è montata in un altro percorso, inseriscilo come cartella homes nella sezione Synology Photos.
Un utente è segnato “nessun accesso”
L'utente di Phorga non può leggere quella cartella home. Dai all'utente phorga Lettura/Scrittura sulla cartella condivisa homes e verifica che user: nel file compose contenga il suo uid e gid.
Il salvataggio fallisce con “permission denied”
La cartella config deve essere scrivibile per l'utente in user:. Monta la cartella (./config:/config), non solo config.yaml.
La pagina non si apre
Controlla che il container sia in esecuzione e che il suo log non mostri errori. Synology: controlla la regola del proxy inverso (destinazione localhost, porta 8080) e il firewall. Altro computer: con 127.0.0.1 nella porta, solo quel computer può aprire la pagina.
Il browser chiede continuamente la password
Va bene qualsiasi nome utente; la password deve corrispondere esattamente a PHORGA_WEB_UI_PASSWORD. Dopo averla cambiata, il container va ricreato.
Le foto spostate non compaiono in Synology Photos
Synology Photos deve prima indicizzare le nuove cartelle. Attendi qualche minuto; se non compaiono ancora, riavvia l'indicizzazione nelle impostazioni di Synology Photos.
