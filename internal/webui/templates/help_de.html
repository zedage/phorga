{{call .T "guide_toc_synology"}}

Phorga läuft direkt auf dem NAS, im Container Manager. Du brauchst DSM 7.2 oder neuer und ein Administratorkonto. Alle Schritte erledigst du in DSM im Browser.

  1. Container Manager installieren. Paket-Zentrum → nach „Container Manager“ suchen → Installieren. Wenn du Synology Photos nutzt, ist der Benutzer-Home-Dienst schon aktiv; sonst schalte ihn unter Systemsteuerung → Benutzer und Gruppe → Erweitert → Benutzer-Home ein.
  2. Einen Benutzer für Phorga anlegen. Systemsteuerung → Benutzer und Gruppe → Erstellen. Name phorga, dazu ein langes zufälliges Passwort (du brauchst es nicht wieder). Bei den Berechtigungen für gemeinsame Ordner gibst du docker und homes Lesen/Schreiben. Bei den Anwendungsberechtigungen verweigerst du alles; Phorga meldet sich nie bei DSM an.
  3. Ordner anlegen. Öffne in der File Station docker, lege den Ordner phorga an und darin die Ordner config und state.
  4. Benutzer-ID herausfinden. Systemsteuerung → Aufgabenplaner → Erstellen → Geplante Aufgabe → Benutzerdefiniertes Skript. Name phorga id, Benutzer root, „Aktiviert“ abwählen; unter Aufgabeneinstellungen den Befehl id phorga > /volume1/docker/phorga/id.txt eintragen. Speichern, die Aufgabe markieren, Ausführen wählen und docker/phorga/id.txt in der File Station öffnen: uid=1030(phorga) gid=100(users) bedeutet 1030:100. Danach die Aufgabe löschen.
  5. Projekt erstellen. Container Manager → Projekt → Erstellen. Projektname phorga, Pfad /docker/phorga, Quelle „docker-compose.yml erstellen“, und einfügen: 
    {{.Data.ComposeSynology}}
    Ersetze 1030:100 durch die Zahlen aus Schritt 4 und choose-a-long-password durch dein eigenes Passwort für die Web-Oberfläche. Weiter, die Webportal-Einstellungen überspringen, Fertig. Der Container Manager lädt Phorga herunter und startet es.
  6. Per HTTPS erreichbar machen. Systemsteuerung → Anmeldeportal → Erweitert → Reverse Proxy → Erstellen: Name Phorga; Quelle Protokoll HTTPS, Hostname *, Port 8443; Ziel Protokoll HTTP, Hostname localhost, Port 8080. Speichern. Ist die DSM-Firewall aktiv, gib Port 8443 frei (Systemsteuerung → Sicherheit → Firewall).
  7. Phorga öffnen. Öffne auf einem Gerät in deinem Netz https://<NAS-Adresse>:8443/ui, z. B. https://192.168.1.20:8443/ui. Hat dein NAS ein eigenes Zertifikat, warnt der Browser einmal; zu Hause ist das normal. Melde dich mit einem beliebigen Benutzernamen und deinem Passwort an und mach weiter bei {{call .T "guide_toc_setup"}}.

{{call .T "guide_toc_other"}}

Phorga läuft auf einem Rechner, der immer an ist, etwa einem Mac mini, einem Intel NUC oder einem Heimserver, und arbeitet über eine Netzwerkfreigabe auf dem NAS.

  1. Docker installieren. macOS und Windows: Docker Desktop, in den Einstellungen „Start Docker Desktop when you sign in“ einschalten. Linux: Docker Engine mit dem Compose-Plugin.
  2. Zugriff auf dem NAS erlauben. Lege in DSM den Benutzer phorga mit Lesen/Schreiben auf homes an (Schritt 2 der Synology-Anleitung) und prüfe, dass SMB aktiv ist (Systemsteuerung → Dateidienste → SMB).
  3. Freigabe verbinden. macOS: Finder → Gehe zu → Mit Server verbinden → smb://<NAS-Adresse>/homes, als phorga anmelden; die Freigabe erscheint als /Volumes/homes. Damit sie nach einem Neustart wieder verbunden wird, füge sie unter Systemeinstellungen → Allgemein → Anmeldeobjekte hinzu. Linux: einhängen, etwa mit dieser Zeile in /etc/fstab (die Datei mit den Zugangsdaten enthält username=phorga und password=…): 
    //192.168.1.20/homes  /mnt/nas-homes  cifs  credentials=/etc/phorga-nas,uid=1000,gid=1000,_netdev  0  0
  4. Projekt erstellen. Lege in deinem Benutzerordner einen Ordner phorga an, darin die Ordner config und state, und speichere dort dies als docker-compose.yml: 
    {{.Data.ComposeOther}}
    Setze user: auf die Ausgabe von id -u und id -g, das Passwort auf dein eigenes und unter Linux die Freigabe auf deinen Einhängepunkt.
  5. Phorga starten. Im Terminal: cd ~/phorga && docker compose up -d. Öffne auf diesem Rechner http://127.0.0.1:8080/ui, melde dich mit beliebigem Benutzernamen und deinem Passwort an und mach weiter bei {{call .T "guide_toc_setup"}}.
  6. Laufen lassen. Der Rechner darf nicht in den Ruhezustand gehen (macOS: Systemeinstellungen → Energie → Automatischen Ruhezustand verhindern). Der Container sieht nur eine Freigabe, die beim Start verbunden war: Nach dem erneuten Verbinden docker compose restart ausführen.

{{call .T "guide_toc_setup"}}

  1. Benutzer wählen. Auf der Konfigurationsseite listet „Synology-Photos-Benutzer“ alle mit einer Synology-Photos-Bibliothek. Hake die Benutzer an, deren Handy-Uploads Phorga sortieren soll, und klicke Ausgewählte Benutzer hinzufügen.
  2. Profil prüfen. Jeder Benutzer bekommt ein Profil, das jede Nacht um 03:00 neue Dateien aus Photos/MobileBackup nach Photos/<Jahr>/<Monat> verschiebt. Es startet als Probelauf (Dry-Run): Phorga schreibt nur ins Log, was es tun würde. Klicke auf das Profil, um die Uhrzeit oder die Ordnerstruktur zu ändern.
  3. Speichern. Speichern schreibt die Konfigurationsdatei und plant die Jobs sofort ein. Ein Neustart ist nicht nötig.
  4. Probelauf prüfen. Nach dem ersten Lauf zeigt die Statusseite, wie viele Dateien verschoben würden, und das Container-Log nennt jede Datei (Container Manager → Container → phorga → Protokoll, oder docker compose logs phorga). Um es sofort zu testen, setze den Zeitplan auf */5 * * * * (alle 5 Minuten) und danach wieder zurück.
  5. Probelauf ausschalten. Sieht das Log richtig aus, öffne das Profil, entferne den Haken bei Dry-Run und speichere. Ab dem nächsten Lauf verschiebt Phorga die Dateien. Synology Photos zeigt sie in den neuen Ordnern, sobald es sie indexiert hat. Prüfe nach dem ersten echten Lauf, dass die Synology-Photos-App auf dem Handy die verschobenen Fotos nicht erneut hochlädt.
  6. Optional: Duplikate finden. Füge unter „Dedup-Jobs“ einen Job hinzu, der Ordner vergleicht und Kopien desselben Fotos findet. Auch er startet als Probelauf, und er verschiebt Duplikate nur in einen Ordner deiner Wahl; er löscht nie etwas.

{{call .T "guide_toc_remote"}}

Wer die Web-Oberfläche öffnen kann, kann ändern, welche Dateien Phorga verschiebt. So schützt du sie:

  • Immer ein Passwort setzen mit PHORGA_WEB_UI_PASSWORD, wie in den Compose-Dateien oben. Nimm ein langes: Nach Fehlversuchen wird nichts gesperrt. Der Browser fragt einmal pro Sitzung danach. Zum Ändern die Compose-Datei bearbeiten und den Container neu erstellen (Container Manager → Projekt → phorga → YAML-Konfigurationen → Bearbeiten, oder docker compose up -d).
  • Synology: Der Reverse Proxy (Schritt 6) bringt HTTPS, und weil der Container-Port auf 127.0.0.1 bleibt, führt nur der Proxy hinein. Um nur dein Heimnetz zuzulassen, erstelle ein Zugriffssteuerungsprofil (Systemsteuerung → Anmeldeportal → Erweitert → Zugriffssteuerungsprofil), das z. B. 192.168.1.0/24 erlaubt und alles andere verweigert, und wähle es in der Reverse-Proxy-Regel aus. Mit eigener Domain trägst du sie statt * als Hostname ein und weist ihr Zertifikat unter Systemsteuerung → Sicherheit → Zertifikat → Einstellungen zu.
  • Anderer Rechner: Ändere den Port auf "8080:8080" und führe docker compose up -d aus. Dann öffne http://<Rechner-Adresse>:8080/ui. Ohne HTTPS geht das Passwort unverschlüsselt durchs Netz; das ist nur in einem Heimnetz vertretbar, dem du vertraust. Für HTTPS setze einen Reverse Proxy wie Caddy davor.
  • Nie den Port im Router ins Internet weiterleiten. Unterwegs verbindest du dich per VPN mit deinem Heimnetz (z. B. Synology VPN Server oder Tailscale).

{{call .T "guide_toc_trouble"}}

„Home-Ordner nicht gefunden“
Der Container sieht den homes-Ordner nicht. Prüfe das Volume /volume1/homes:/homes; auf einem anderen Rechner, ob die Freigabe verbunden ist. Ist er unter einem anderen Pfad eingehängt, trage diesen im Bereich Synology Photos als homes-Ordner ein.
Ein Benutzer ist mit „kein Zugriff“ markiert
Phorgas Benutzer darf diesen Home-Ordner nicht lesen. Gib dem Benutzer phorga Lesen/Schreiben auf den gemeinsamen Ordner homes und prüfe, dass user: in der Compose-Datei seine uid und gid enthält.
Speichern scheitert mit „permission denied“
Der Ordner config muss für den Benutzer in user: beschreibbar sein. Hänge den Ordner ein (./config:/config), nicht config.yaml allein.
Die Seite öffnet sich nicht
Prüfe, dass der Container läuft und sein Log keinen Fehler zeigt. Synology: Prüfe die Reverse-Proxy-Regel (Ziel localhost, Port 8080) und die Firewall. Anderer Rechner: Mit 127.0.0.1 im Port kann nur dieser Rechner die Seite öffnen.
Der Browser fragt immer wieder nach dem Passwort
Jeder Benutzername geht; das Passwort muss genau PHORGA_WEB_UI_PASSWORD entsprechen. Nach einer Änderung muss der Container neu erstellt werden.
Verschobene Fotos erscheinen nicht in Synology Photos
Synology Photos muss neue Ordner zuerst indexieren. Warte ein paar Minuten; erscheinen sie dann noch nicht, starte die Indexierung in den Einstellungen von Synology Photos neu.
