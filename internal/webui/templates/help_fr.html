{{call .T "guide_toc_synology"}}

Phorga tourne directement sur le NAS, dans Container Manager. Il faut DSM 7.2 ou plus récent et un compte administrateur. Toutes les étapes se font dans DSM, depuis le navigateur.

  1. Installer Container Manager. Centre de paquets → chercher « Container Manager » → Installer. Si vous utilisez Synology Photos, le service d'accueil utilisateur est déjà actif ; sinon, activez-le dans Panneau de configuration → Utilisateur et groupe → Avancé → Accueil de l'utilisateur.
  2. Créer un utilisateur pour Phorga. Panneau de configuration → Utilisateur et groupe → Créer. Nommez-le phorga et donnez-lui un long mot de passe aléatoire (vous n'en aurez plus besoin). Dans les autorisations des dossiers partagés, accordez Lecture/Écriture sur docker et homes. Dans les autorisations des applications, refusez tout ; Phorga ne se connecte jamais à DSM.
  3. Créer les dossiers. Dans File Station, ouvrez docker, créez le dossier phorga et, à l'intérieur, les dossiers config et state.
  4. Trouver l'ID de l'utilisateur. Panneau de configuration → Planificateur de tâches → Créer → Tâche planifiée → Script défini par l'utilisateur. Nom phorga id, utilisateur root, décochez « Activé » ; dans les paramètres de la tâche, saisissez la commande id phorga > /volume1/docker/phorga/id.txt. Enregistrez, sélectionnez la tâche, cliquez sur Exécuter, puis ouvrez docker/phorga/id.txt dans File Station : uid=1030(phorga) gid=100(users) signifie 1030:100. Supprimez ensuite la tâche.
  5. Créer le projet. Container Manager → Projet → Créer. Nom du projet phorga, chemin /docker/phorga, source « Créer docker-compose.yml », et collez : 
    {{.Data.ComposeSynology}}
    Remplacez 1030:100 par les nombres de l'étape 4 et choose-a-long-password par votre propre mot de passe pour l'interface web. Suivant, ignorez les réglages du portail web, Terminé. Container Manager télécharge Phorga et le démarre.
  6. Le rendre accessible en HTTPS. Panneau de configuration → Portail de connexion → Avancé → Proxy inversé → Créer : nom Phorga ; source protocole HTTPS, nom d'hôte *, port 8443 ; destination protocole HTTP, nom d'hôte localhost, port 8080. Enregistrez. Si le pare-feu de DSM est actif, autorisez le port 8443 (Panneau de configuration → Sécurité → Pare-feu).
  7. Ouvrir Phorga. Depuis un appareil de votre réseau, ouvrez https://<adresse du NAS>:8443/ui, p. ex. https://192.168.1.20:8443/ui. Si le NAS utilise son propre certificat, le navigateur avertit une fois ; à la maison, c'est normal. Connectez-vous avec n'importe quel nom d'utilisateur et votre mot de passe, puis continuez avec {{call .T "guide_toc_setup"}}.

{{call .T "guide_toc_other"}}

Phorga tourne sur un ordinateur toujours allumé, comme un Mac mini, un Intel NUC ou un serveur domestique, et travaille sur le NAS via un partage réseau.

  1. Installer Docker. macOS et Windows : Docker Desktop, avec « Start Docker Desktop when you sign in » activé dans ses réglages. Linux : Docker Engine avec le plugin Compose.
  2. Autoriser l'accès sur le NAS. Dans DSM, créez l'utilisateur phorga avec Lecture/Écriture sur homes (étape 2 du guide Synology) et vérifiez que SMB est actif (Panneau de configuration → Services de fichiers → SMB).
  3. Connecter le partage. macOS : Finder → Aller → Se connecter au serveur → smb://<adresse du NAS>/homes, connectez-vous en tant que phorga ; le partage apparaît sous /Volumes/homes. Pour le reconnecter après un redémarrage, ajoutez-le dans Réglages Système → Général → Ouverture. Linux : montez-le, par exemple avec cette ligne dans /etc/fstab (le fichier d'identifiants contient username=phorga et password=…) : 
    //192.168.1.20/homes  /mnt/nas-homes  cifs  credentials=/etc/phorga-nas,uid=1000,gid=1000,_netdev  0  0
  4. Créer le projet. Créez un dossier phorga dans votre dossier personnel, avec les dossiers config et state à l'intérieur, et enregistrez-y ceci sous docker-compose.yml : 
    {{.Data.ComposeOther}}
    Mettez dans user: la sortie de id -u et id -g, votre propre mot de passe et, sous Linux, votre point de montage pour le partage.
  5. Démarrer Phorga. Dans un terminal : cd ~/phorga && docker compose up -d. Ouvrez http://127.0.0.1:8080/ui sur cet ordinateur, connectez-vous avec n'importe quel nom d'utilisateur et votre mot de passe, et continuez avec {{call .T "guide_toc_setup"}}.
  6. Le garder en marche. L'ordinateur ne doit pas se mettre en veille (macOS : Réglages Système → Énergie → Empêcher la suspension d'activité automatique). Le conteneur ne voit qu'un partage connecté à son démarrage : après avoir reconnecté le partage, lancez docker compose restart.

{{call .T "guide_toc_setup"}}

  1. Choisir les utilisateurs. Sur la page de configuration, « Utilisateurs de Synology Photos » liste tous ceux qui ont une bibliothèque Synology Photos. Cochez les utilisateurs dont Phorga doit trier les envois du téléphone, puis cliquez sur Ajouter les utilisateurs cochés.
  2. Vérifier le profil. Chaque utilisateur reçoit un profil qui déplace chaque nuit à 03:00 les nouveaux fichiers de Photos/MobileBackup vers Photos/<année>/<mois>. Il démarre en exécution à blanc : Phorga écrit seulement dans son journal ce qu'il ferait. Cliquez sur le profil pour changer l'heure ou la structure des dossiers.
  3. Enregistrer. L'enregistrement écrit le fichier de configuration et planifie aussitôt les tâches. Aucun redémarrage n'est nécessaire.
  4. Vérifier l'exécution à blanc. Après la première exécution, la page de statut indique combien de fichiers seraient déplacés, et le journal du conteneur cite chaque fichier (Container Manager → Conteneur → phorga → Journal, ou docker compose logs phorga). Pour essayer tout de suite, réglez la planification sur */5 * * * * (toutes les 5 minutes), puis remettez-la comme avant.
  5. Désactiver l'exécution à blanc. Si le journal est correct, ouvrez le profil, décochez Exécution à blanc et enregistrez. Dès l'exécution suivante, Phorga déplace les fichiers. Synology Photos les affiche dans leurs nouveaux dossiers une fois indexés. Après la première vraie exécution, vérifiez que l'application Synology Photos du téléphone ne renvoie pas les photos déplacées.
  6. Facultatif : trouver les doublons. Sous « Tâches de détection des doublons », ajoutez une tâche qui compare des dossiers et trouve les copies d'une même photo. Elle démarre aussi en exécution à blanc et ne fait que déplacer les doublons vers un dossier de votre choix ; elle ne supprime jamais rien.

{{call .T "guide_toc_remote"}}

Quiconque peut ouvrir l'interface web peut changer les fichiers que Phorga déplace. Protégez-la ainsi :

  • Définissez toujours un mot de passe avec PHORGA_WEB_UI_PASSWORD, comme dans les fichiers compose ci-dessus. Choisissez-en un long : rien n'est bloqué après des essais erronés. Le navigateur le demande une fois par session. Pour le changer, modifiez le fichier compose et recréez le conteneur (Container Manager → Projet → phorga → Configurations YAML → Modifier, ou docker compose up -d).
  • Synology : le proxy inversé (étape 6) ajoute HTTPS et, comme le port du conteneur reste sur 127.0.0.1, le proxy est le seul accès. Pour n'autoriser que votre réseau domestique, créez un profil de contrôle d'accès (Panneau de configuration → Portail de connexion → Avancé → Profil de contrôle d'accès) qui autorise p. ex. 192.168.1.0/24 et refuse tout le reste, et sélectionnez-le dans la règle du proxy inversé. Avec votre propre domaine, utilisez-le comme nom d'hôte à la place de * et attribuez-lui son certificat dans Panneau de configuration → Sécurité → Certificat → Paramètres.
  • Autre ordinateur : changez le port en "8080:8080" et lancez docker compose up -d. Ouvrez ensuite http://<adresse de l'ordinateur>:8080/ui. Sans HTTPS, le mot de passe traverse le réseau en clair, ce qui n'est acceptable que dans un réseau domestique de confiance ; pour HTTPS, placez devant un proxy inversé comme Caddy.
  • Ne redirigez jamais le port vers Internet dans votre routeur. En déplacement, connectez-vous à votre réseau domestique par VPN (par exemple Synology VPN Server ou Tailscale).

{{call .T "guide_toc_trouble"}}

« dossier des homes introuvable »
Le conteneur ne voit pas le dossier homes. Vérifiez le volume /volume1/homes:/homes ; sur un autre ordinateur, que le partage est connecté. S'il est monté ailleurs, saisissez ce chemin comme dossier des homes dans la section Synology Photos.
Un utilisateur est marqué « pas d'accès »
L'utilisateur de Phorga ne peut pas lire ce dossier personnel. Accordez à l'utilisateur phorga Lecture/Écriture sur le dossier partagé homes et vérifiez que user: dans le fichier compose contient son uid et son gid.
L'enregistrement échoue avec « permission denied »
Le dossier config doit être accessible en écriture pour l'utilisateur de user:. Montez le dossier (./config:/config), pas config.yaml seul.
La page ne s'ouvre pas
Vérifiez que le conteneur tourne et que son journal ne montre pas d'erreur. Synology : vérifiez la règle du proxy inversé (destination localhost, port 8080) et le pare-feu. Autre ordinateur : avec 127.0.0.1 dans le port, seul cet ordinateur peut ouvrir la page.
Le navigateur redemande sans cesse le mot de passe
N'importe quel nom d'utilisateur convient ; le mot de passe doit correspondre exactement à PHORGA_WEB_UI_PASSWORD. Après l'avoir changé, il faut recréer le conteneur.
Les photos déplacées n'apparaissent pas dans Synology Photos
Synology Photos doit d'abord indexer les nouveaux dossiers. Patientez quelques minutes ; si elles n'apparaissent toujours pas, relancez l'indexation dans les réglages de Synology Photos.
